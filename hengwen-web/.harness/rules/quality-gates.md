# Quality Gates

## Definition Of Done

任务只有同时满足以下条件才完成：

- 用户验收条件逐条通过。
- 最终 diff 已自查，无无关修改、调试代码或已知未处理缺陷。
- 所有适用自动化门禁通过。
- UI 改动已完成桌面和移动验证。
- 测试缺口、未验证项和残余风险已如实报告。

## Mandatory Commands

在 `hengwen-web/` 运行：

```bash
npm run lint
npx prettier --check <changed-files...>
npm run build
```

- `lint`：每次代码改动必跑。
- `prettier --check`：每次代码或受格式约束的文档改动必跑，参数必须包含本次所有适用的变更文件。全仓已有格式债务不允许掩盖本次文件失败，也不要求在无关任务中顺手重写历史文件。
- `build`：每次 TypeScript、样式、资源、配置或依赖改动必跑；它同时覆盖 TypeScript 编译和生产构建。
- 纯 Markdown 文档改动可跳过 `build`，但仍须检查路径、链接和 Markdown 格式，并说明跳过原因。

## Tests

当前项目没有 `npm run test` 脚本，因此遵循以下规则：

1. 若任务仅修改现有静态文案或样式，可记录“无测试脚本”，使用 lint、build 和 UI 回归作为证据。
2. 若新增或修改可独立测试的业务逻辑、状态转换、数据适配或缺陷修复，必须在同一任务中增加合适的测试和 `test` 脚本；随后 `npm run test` 成为强制门禁。
3. 若任务明确要求测试，缺少测试基础设施不构成跳过理由；应将新增测试能力纳入任务。因权限或依赖下载无法完成时，状态为 `BLOCKED`，不得标记通过。
4. 已存在测试脚本后，每次代码改动都必须运行 `npm run test`；不得在后续任务中退回“无测试脚本”的例外。

测试应覆盖行为和边界，不以快照或实现细节测试代替关键断言。

## Targeted Checks

根据改动追加检查：

- 路由：直接访问、刷新、前进/后退和未知路径。
- 请求：成功、业务失败、网络失败、超时/取消和重复提交。
- 状态：初始、加载、空、错误、恢复和并发更新。
- 表单：有效输入、无效输入、边界值和服务端错误。
- UI：`rules/frontend.md` 规定的视口、状态、交互和控制台。
- 依赖/构建配置：干净安装可行性、开发启动和生产构建。

## Failure Policy

- 任一强制命令非零退出即为 `FAIL`。
- 不允许通过禁用规则、删除测试、扩大 ignore、使用 `@ts-ignore` 或降低断言来制造通过。
- 修复后先重跑失败命令，再重跑可能受影响的完整门禁。
- 若发现疑似既有失败，使用未修改基线或可靠历史证据确认；无法确认时按当前失败报告。

## Evidence

质量报告必须记录命令、结果和必要摘要。禁止使用“应该通过”“未发现明显问题”代替实际验证。
